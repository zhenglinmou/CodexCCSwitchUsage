# Codex CCSwitch Usage v2

[返回版本选择](../README.md) · [查看 v1 文档](./V1.md)

v2 已从“当前供应商余额条”发展为完整的本机余额中心：同一个 Node 宿主负责读取 CCSwitch、查询额度、维护缓存、向 Codex/ChatGPT 输入栏注入余额，并提供 All API Hub 与本机只读接口。

## 当前状态

本文对应当前 v2 源码状态如下：

- 包版本为 `2.0.20`，维护分支为 `v2`，当前注入器版本为 `94`，浏览器伴侣版本为 `0.1.25`。
- 自动化检查使用仓库根目录的 `npm test`；开发热更新不会关闭或重启现有 `ChatGPT.exe` 根进程。Codex Desktop 的具体兼容性仍取决于当前输入栏 DOM，升级 Codex 后应重新执行对应的实时回归。
- 宿主绑定启动时确认的 `ChatGPT.exe` 根 PID；关闭 Codex 后宿主会释放 Hub、数据库等资源并彻底退出，宿主热重启则不会影响 Codex。该检测不保持长期 CDP WebSocket。
- 完整自动化测试全部通过，覆盖注入器、动作队列、CDP 隔离、宿主调度、进程生命周期、Hub、供应商路由与响应 schema、浏览器伴侣协议、安装脚本和回归路径；实时数量以 `npm test` 输出为准。
- CCSwitch 数据库仍保持只读；v2 不再执行或改写供应商的 `usage_script`。
- v2 已可作为日常使用版本，但仍依赖 Codex Desktop 的页面结构。Codex 更新后如果输入栏 DOM 发生破坏性变化，可能需要同步更新注入器。

### 输入栏适配

余额根容器始终占满“左侧原生控件”和“右侧原生控件”之间的动态空闲通道，余额内容在该通道内居中，而不是相对整个输入框居中。

| 界面 | 当前状态 | 行为 |
|---|---|---|
| Codex 模式 | 已适配 | 保留原生模型自由通道；模型、推理强度、权限和侧栏变化不会把余额挤到右侧。 |
| ChatGPT Work | 已适配 | 可穿过原生 `display: contents` 包装层，挂入 Work 的完整自由通道。 |
| ChatGPT Chat 单行 | 已适配 | 保持原生单行输入栏布局，余额与 ChatGPT 模型、语音和发送控件同排。 |
| ChatGPT Chat 多行 | 已适配 | 输入超过单行容量后，余额自动进入下方完整自由通道并重新居中。 |
| 窄窗口/侧栏挤压 | 已适配 | 按 `full → compact → no-extra → no-used → no-meter → no-dot → icon` 逐级隐藏低优先级字段；根容器不向左溢出，也不覆盖原生按钮。 |
| 非输入页 | 已适配 | Settings、Plugins、Automations、Pull Requests 等页面不保留余额节点；返回任务页时自动恢复。 |

页面存在多个有效输入栏时会创建同步镜像；输入栏被 React 替换、折叠或重新挂载时，注入器会恢复根节点。普通输入、滚动、菜单动画和未跨越响应式阈值的尺寸变化不会触发持续的逐帧布局计算。

### All API Hub

- 自动读取 CCSwitch 中全部 `app_type=codex` 供应商，不维护第二份账号清单。
- Hub 默认使用宽松卡片，并可切换为紧凑列表；宽松模式在常规桌面宽度保持双列，每张卡片固定展示已用、剩余和总额三项指标，窄屏再切换为单列。视图选择会与收藏、排序、已忽略供应商和浏览器别名一起记住。两种视图均支持名称/域名/状态搜索，以及按推荐顺序、名称、剩余额度比例、更新时间或查询耗时排序。浏览器型供应商在状态区直接显示对应 Edge / Chrome 或本机别名；Hub 优先采用账号绑定、上次手动选择、上次成功结果和唯一已验证官网会话，无法确定时明确显示“未指定”而不猜测。默认顺序为当前供应商、需处理供应商、收藏供应商和其他供应商；界面偏好只写入本机 `runtime\hub-preferences.json`，不修改 CCSwitch 数据库。
- 首次进入 Hub 会显示一次性检查区，确认 Codex 页面、当前供应商数据和按需浏览器连接状态；完成后只保存检查完成标记，不保存新的身份或凭据数据。非当前供应商可以从“更多操作”中忽略，并在“已忽略”筛选中恢复；当前 CCSwitch 供应商始终保留。全量刷新只查询工作区内仍在使用的供应商，不会请求已忽略项。
- 在“需处理”筛选中点击重试后，卡片会在查询完成前保持原筛选和排序位置，按钮切换为禁用的“查询中”，避免卡片消失、重复请求或布局跳动。查询期间刷新 Hub 页面也会自动接管未完成操作，完成后更新为真实结果。
- 浏览器待办按具体 Edge / Chrome 实例分组，集中显示待认证、待同步、待绑定和待重检供应商，可处理或重新检查当前组，不会误触发全量刷新。认证动作会直接发送到该浏览器；用户离开 Hub 完成官网认证并返回后只自动检查一次，失败时保留“我已完成认证，重新检查”，不持续轮询或重复打开网站。手动改用另一个浏览器后会按供应商记住选择。
- “系统检查”抽屉统一显示宿主、Codex 页面连接、CCSwitch 变更监听、浏览器伴侣版本与供应商异常。多个 Edge / Chrome 实例可以保存本机别名；供应商列表与诊断项提供登录、会话同步、账号绑定、模板测试和重试入口。脱敏诊断报告不包含 API Key、Cookie、Bearer Token 或请求正文。
- Hub 页脚的“隐私与安全”入口说明本机数据留存、CCSwitch 只读、浏览器权限、外部通信和脱敏诊断范围；完整政策与漏洞报告方式见[隐私与安全政策](../SECURITY.md)。
- Hub 统一展示当前供应商、查询状态、已用、剩余、总额、更新时间、数据来源和单次查询耗时。
- 支持刷新单个供应商或并发刷新全部供应商；浏览器型供应商使用独立串行通道，不会占满直接 API 查询并发。
- 常规宽度下，输入栏显示独立的 All API Hub 图标；余额文字本身不跳转。极限压缩时入口保留在刷新按钮弹层中。
- 输入栏四宫格图标会先显示 CCSwitch 当前供应商最近 10 条请求，包含实际模型、输入/输出/缓存 Token、本次费用、状态、总耗时/首字耗时和相对时间；OpenAI Official 直接使用 Codex 官方本机会话的 `token_count`，ChatGPT 订阅没有逐请求扣费金额时费用显示 `--`；弹层底部的“打开 All API Hub”再进入完整 Hub。
- 每张卡片的“模板”可独立选择余额额度与逐请求 Token/扣费模板，支持自动识别、测试所选、保存和恢复内置；同一弹窗仍列出脱敏后的请求结构，不显示认证原文。自动识别在 12 秒总预算内并行验证余额与逐请求能力，同一 URL 和认证组合只读取一次响应；命中高优先级模板后会取消仍在后台运行的投机请求。逐请求自动识别固定验证最近 10 条：非空日志必须包含带有效请求字段的 `type = 2` 消费行或 `type = 5` 请求错误行，全 0 的真实错误记录仍有效，空/null 占位字段不会触发识别；空日志由 `/api/status` 佐证，或由至少两条本地成功请求严格关联到同一账户日志 `token_id`。HTTP 401、无法归属和同名未关联记录均失败关闭，识别成功后仍需用户显式保存。完整规则见[逐请求用量接口说明](./REQUEST_USAGE.md)。
- 打开 Hub 只读取缓存，不自动刷新。只有 CCSwitch 当前供应商每五分钟自动查询，其他供应商由用户手动刷新。
- Hub 缓存带有不含凭据原文的供应商配置指纹；API Key、Base URL 或账号配置变化后不会继续把旧账号余额标为正常。余额成功时间与最近尝试时间分别记录，查询失败不会把旧余额伪装成“刚刚更新”。
- 浏览器型供应商、OpenAI 等具有固定官方登录地址的供应商始终显示独立登录入口；查询失败不会隐藏该入口。

### 供应商查询能力

| 类型 | 查询方式 | 当前能力 |
|---|---|---|
| OpenAI | 本机账户 Token 请求 WHAM；逐请求读取 Codex 官方本机会话；必要时由浏览器伴侣回退余额 | 展示主要额度窗口、重置时间与计划信息；逐请求展示官方输入/输出/缓存 Token，并把订阅模式下不可用的货币扣费明确显示为 `--`。 |
| CLIProxyAPI / CPA | 只读扫描 `~/.cli-proxy-api` 中的 Codex 账号 | 查询可用账号并汇总额度，不修改账号文件。 |
| 浏览器型供应商 | Edge/Chrome 伴侣在同源页面使用 Cookie 与数字用户 ID | 支持 WAF、会话同步、明确登录失效识别和手动官网认证。浏览器型供应商不公开 Token 列表时，可把每个不同 API Key 显式绑定到 Edge 或 Chrome；刷新只调用绑定账号，浏览器换号会清除旧额度并要求重新绑定。单一浏览器型供应商 Key 仍可使用唯一有效浏览器会话自动查询。 |
| 第三方公益站 | 有限 API Key 直接查询；无限 Key 由浏览器伴侣读取所属账户额度；Cloudflare/WAF 时也可由浏览器同源回退 | 按各站点已配置的 API 域名精确匹配并套用对应换算；无限 Key 的真实 `total_used` 会与账户已用量合并，不把占位值当作余额；若仍被 WAF 拦截，会明确降级显示 CCSwitch 本地请求次数和成本估算，不伪造剩余或总额。 |
| DeepSeek | 官方 `/user/balance` | 使用 CCSwitch API Key 查询真实余额。 |
| PackyCode / 同结构 New API | New API 重置周期有效额度 | `/api/usage/token/` 同时返回 `total_available`、`total_used` 与 `quota_reset_period` 时，有限或无限 Key 都直接展示有效额度和重置周期，不要求官网登录；该更具体的模板先于标准 New API 模板识别。 |
| 窗口额度站 | 第三方 `/user/balance` | 解析 3 小时与 1 天窗口，并要求每个窗口的 `total = used + remaining`；相同凭据的镜像供应商共享短期成功结果。 |
| 其他 API Key 供应商 | `/models` 健康检查与 CCSwitch 本地统计 | 能确认 API 可用性并展示本地费用；没有已知余额接口时不会伪造真实余额。 |

### CPA 本机范围约定

本机个人使用不把 CLIProxyAPI（CPA）作为需要维护的业务来源。CPA 文件扫描、账号启用/停用、Token 过期和多账号汇总选择等问题，当前不纳入 v2 的验收阻塞或修复范围；发现这类现象时记录即可，不要因此修改或阻塞其他供应商的 v2 工作。只有用户明确要求处理 CPA 时，才重新评估这部分逻辑。

所有供应商查询都有总截止时间；普通 HTTP 重试共享同一时间预算，不会在每次重试时重新计时。并发中的相同查询与 30 秒内的成功结果可以安全复用，缓存键使用凭据哈希，不保存凭据原文。

固定目标的专用适配器会同时检查已配置 API 域名：供应商改名不会破坏正确域名的识别，仅名称关键词不会把凭据改发到固定官网。New API 各变体（包括 Packy 类重置周期扩展）与 DeepSeek 余额响应均使用显式 schema 校验；缺失或非法数值会显示查询异常，合法的余额 `0` 保持为零。

### 后台与性能

- v2 监听 `127.0.0.1:17891`，完全替代旧 Python 余额桥接。
- 刷新和 Hub 点击通过标题中的短期不可见待处理队列传递。队列同时保留 `refresh` 与 `open-hub`，同类连续点击只保留最新动作；宿主每秒读取一次短生命周期 `/json/list` 快照，精确确认整批动作后再执行。
- 连续刷新会合并为“一个正在执行的请求 + 最多一个尾随请求”；旧结果不会覆盖最后一次刷新，查询期间 Hub 点击仍可响应。
- 不保持浏览器级或页面级 CDP WebSocket。只有注入、结果推送、动作确认和五分钟安全审计使用一次性、仅允许 loopback 的连接，并在 `finally` 中断开；握手超时会直接销毁其 TCP socket。每秒一次的本机 `/json/list` HTTP 快照复用单个受限 keep-alive socket，宿主退出时显式销毁，避免重复 TCP 握手而不扩大 CDP 会话生命周期。
- CDP 只接受 URL 严格等于 `app://-/index.html` 的主页面。存在 Browse、MCP App、外部页或辅助 WebView 时，注入会延后而不是连接不确定目标。
- CCSwitch 数据库变化由 `fs.watch` 即时通知；数据库内容未变化时不会重建 Hub 状态或重复刷新。
- Hub 的公开供应商数组、别名选择器和浏览器站点 Origin 列表按供应商快照/状态修订缓存；刷新操作轮询不会重复拼装未变化的卡片数据，浏览器伴侣心跳也不会反复计算同一权限列表。`/v1/health` 与宿主状态只读取供应商数量和刷新状态等轻量摘要。
- `status.json` 与当前供应商余额缓存使用同目录原子替换；完全相同的状态在五分钟心跳前不会重复刷盘。瞬时文件占用只记录为状态/缓存持久化问题，不会把已成功的实时余额误判成供应商查询失败，也不会因此终止宿主。
- 浏览器伴侣使用 25 秒长轮询并连续交接成功批次；新 MV3 Worker 会接管同一客户端的旧轮询，HTTP 断开会立即取消等待。连续连接失败会指数退避，并在第三次失败后交给一分钟 alarm 再唤醒。完整供应商查询、宿主回调等待和浏览器任务分别为 45、44、40 秒；任务携带宿主截止时间并预留 2 秒回传，扩展上下文先执行查询，已有同源标签页只作为单次 8 秒的回退。HTML 或 Cloudflare 挑战响应只检查响应头，不继续等待挑战页正文；`Content-Length` 只用于事前拒绝过大响应，不会把压缩传输长度误当成解压后正文长度。
- 宿主与浏览器伴侣使用协议 v2 协商能力集合；每次任务领取签发一次性结果凭据，并同时绑定精确客户端、浏览器与 Worker 实例，其他客户端或已被替换的 Worker 不能提交结果。连接、会话、长轮询和待处理任务都有硬上限，过期客户端会从内存中删除。版本不兼容时拒绝接收任务并显示明确错误。
- 安装器和源码安装在复制前把安装目录设为仅当前用户、SYSTEM 与 Administrators 可访问；每次启动还会重新加固 `runtime` 与 Hub 连接码。ACL 加固失败时安装或启动会中止，不会带着宽松权限继续运行。
- OpenAI Official 最近请求按文件新旧顺序读取，使用有大小上限的本机派生索引，并只增量解析活跃 JSONL 的追加部分；索引不包含对话正文、访问令牌或请求正文。
- Windows 启动脚本读取当前用户代理；macOS 源码入口优先使用 `HTTP_PROXY`/`HTTPS_PROXY`，未设置时读取 `scutil --proxy`。两种平台都会把本机 Hub 地址加入 `NO_PROXY`，代理值不写入状态或日志。
- 浏览器伴侣只把本机 Hub 设为必需站点权限；Hub 根据当前模板下发精确 HTTPS Origin，第三方供应商站点在伴侣弹窗中由用户逐批授权。站点权限被浏览器扣留时，查询会明确提示授权，不会把 `Failed to fetch` 误判为官网退出登录。

## 当前边界

- Windows 和 macOS 源码模式均要求 Node.js 22 或更高版本；Windows 发布版提供 EXE，macOS 发布版提供 Apple Silicon 与 Intel 的未签名 `.app` 压缩包。
- Codex/ChatGPT 必须在本机 CDP 端口 `9334` 可用；开发热更新不会在端口缺失时擅自重启应用。
- WAF 或网页登录型供应商需要安装并一次性配对浏览器伴侣；插件不会自动接管未授权的浏览器 profile。
- 余额查询不会自动创建或激活第三方网站标签页。只有用户明确点击“同步现有会话”或“去官网认证”时才会操作登录页。
- 新供应商默认使用通用 API 健康检查；如果响应兼容已有结构，可在 Hub 中自动识别或手动选择模板，无需修改代码。标准无限 Key 即使尚未连接浏览器，也会识别为 New API 模板并提示后续登录/同步，而不会降级成未知模板。只有新响应结构才需要增加适配器。
- Hub 是本机工具，不提供远程访问、云同步或多设备账户管理。

## 数据流

v2 的余额数据流只有一个中心：

```text
Codex 余额条 ─┐
All API Hub  ─┼→ v2 Balance Hub → 第三方官网 API / 现有浏览器回调
本机统一接口 ─┘
```

Hub 不执行、也不修改 CCSwitch 中已有的 `usage_script`。数据库原值保持不变；统一接口同时兼容已有的 `/usage/{alias}` 与 `/v1/balance/{alias}` 路径。

v1 的脚本执行方式和返回格式已单独保留在 [v1 文档](./V1.md) 与 [v1 `usage_script` 格式说明](../USAGE_SCRIPT_FORMAT.md) 中。

## 安全与运行边界

本项目在 Windows 和 macOS 上以本机模式运行。开发与运行需要 Node.js 22 或更高版本；Codex 必须通过本地 CDP 调试端口与插件宿主连接。

完整的数据留存、浏览器权限、诊断报告与漏洞报告边界见 [隐私与安全政策](../SECURITY.md)。

- 不修改 `app.asar`、MSIX 或 Codex 配置。
- CCSwitch 数据库只读。
- CDP 只连接已确认的 Codex 主文档；不会连接 Browse、MCP App、`about:blank`、外部网页或其他原生辅助 WebView。
- Hub 只监听 `127.0.0.1:17891`，并只接受端口匹配的 `127.0.0.1`、`localhost` 或 `::1` Host。管理页面和写操作使用首次启动生成并保存在 `runtime` 的随机路径令牌。
- API Key、Cookie 与 Token 只在本机宿主内存中用于请求，不发送到 Hub 页面，也不写日志。
- 自定义供应商接口必须使用 HTTPS；`127.0.0.1`、`localhost` 和 `::1` 可直接使用 HTTP。确需访问公司内部 HTTP 服务时，可在 `~/.cc-switch/allow-http-origins.json` 中按“供应商 ID + 精确 Origin（含端口）”单独放行；该例外只供 Node 宿主直连，不会给浏览器伴侣增加 HTTP 通配权限。
- WAF 查询通过 `browser-companion` 使用现有 Edge / Chrome profile 的登录状态；Cookie 原文不会回传。
- 不运行额外的 Codex 实例守护进程。

## 本机只读余额接口

```text
GET /v1/health
GET /v1/providers
GET /v1/balance/{provider-id-or-alias}
GET /v1/balances
GET /usage/{provider-id-or-alias}
```

`/v1/balance/*`、`/v1/balances` 和兼容用的 `/usage/*` 都只返回 Hub 当前缓存及成功/尝试时间，不会因读取或轮询访问第三方。Hub 页面刷新使用带随机路径令牌的本机 `POST /api/{token}/refresh`，接口接受刷新请求后返回 `202`，实际结果随后通过受保护的 state 接口更新。

需要管理权限的接口都使用同一个运行时令牌路径：

```text
GET  /api/{token}/state
POST /api/{token}/refresh
GET  /api/{token}/templates?providerId={provider-id}
POST /api/{token}/template-probe
POST /api/{token}/template-selection
POST /api/{token}/request-usage
```

模板测试和逐请求查询只在用户显式操作或打开弹层时执行；模板选择保存到本机 `runtime` 绑定文件，余额与逐请求模板彼此独立。运行时令牌只保存在本机 `runtime\hub-token`，不要复制到公开 Issue、日志或截图中。

## 连接现有浏览器

浏览器型供应商，以及使用无限 API Key 的已配置第三方公益站，需要一次性连接浏览器伴侣。每个 v2 GitHub Release 都同时提供同一应用版本的主安装器，以及当前伴侣版本对应的 ZIP 和签名 CRX：

- 普通 Edge / Chrome 用户优先下载 `CCSwitch-Browser-Companion-<companion-version>.zip`，解压后按下面的“加载解压缩的扩展”步骤安装。
- `CCSwitch-Browser-Companion-<companion-version>.crx` 使用持续保存的私钥签名，适合支持 CRX 导入或受管策略部署的环境；Chrome / Edge 仍可能拦截非商店来源的直接 CRX 安装，遇到拦截时使用 ZIP。
- 不需要浏览器登录态、Cookie 或 WAF 查询的直接 API 供应商不需要安装伴侣。

安装和配对步骤如下：

1. 在 `edge://extensions` 或 `chrome://extensions` 启用“开发人员模式”。
2. 选择“加载解压缩的扩展”，目录指向项目中的 `browser-companion`。
3. 打开 All API Hub，点击“连接现有浏览器”复制连接码。
4. 点击“CCSwitch 余额伴侣”图标，粘贴连接码并保存。
5. 在伴侣弹窗点击站点授权按钮；Edge / Chrome 出现确认框时允许 Hub 当前列出的精确供应商站点。

如果同一站点的不同账号分别登录在 Edge 和 Chrome，请在两个浏览器中各加载一次伴侣，保存同一个 Hub 连接码并分别授权。Hub 会分别显示“Chrome 已连接”“Edge 已连接”，供应商卡片也会提供定向验证入口。宿主会把操作定向到所选浏览器，并用供应商 API Key 的脱敏标识核验账号归属；不会把完整 API Key 发给浏览器，也不会把一个账号的余额显示到另一个供应商。

浏览器型供应商 当前不公开可用于 API Key 归属核验的 Token 列表。只有一个不同 浏览器型供应商 Key 时可以继续使用唯一有效浏览器会话；存在多个不同 Key 时，先在对应卡片点击“绑定 Edge”或“绑定 Chrome”。绑定关系按 API Key 隔离并持久化，后续“刷新”和“刷新全部”都只投递到该浏览器。绑定只保存不可逆账号指纹；如果该浏览器切换了浏览器型供应商 账号，Hub 会拒绝新账号响应、清空旧额度并显示“需要绑定”。

连接码只需保存一次。连接码、固定 `clientId`、对应浏览器类型和已成功验证站点的 origin 提示保存在当前浏览器 profile 的 `chrome.storage.local`；浏览器启动、MV3 后台唤醒或 Balance Hub 宿主重连时，伴侣会自动重新连接并恢复这些站点提示。旧版曾在 Chrome 与 Edge 间复制相同 `clientId` 时，`0.1.23` 会自动为当前浏览器迁移出独立身份，宿主本身也会按浏览器隔离连接，避免互相覆盖。

浏览器伴侣源码升级后，需要在扩展管理页点一次“重新加载”。连接码和会话提示不会丢失；如果宿主与伴侣协议版本不一致，扩展弹窗会显示连接异常，重新加载当前 `browser-companion` 即可恢复。

如果伴侣显示已连接，但浏览器型供应商或第三方公益站等浏览器站点同时出现 `Failed to fetch`，先检查扩展详情中的“站点访问权限”。打开“自动允许在以下站点上访问”，或在伴侣弹窗重新点击“授予网站查询权限”，即可恢复；这不是各供应商同时退出登录。

站点 Cookie 仍由 Edge / Chrome 自己持久化，伴侣不会把 Cookie 原文传给 Node。伴侣只保存已成功验证且有界的 HTTPS origin，以及 New API 余额接口所需的纯数字用户 ID；不会保存 localStorage 原文、Token 或其他认证数据。宿主重启后会恢复这些提示，再用真实同源响应验证登录状态；明确的认证失败会清除提示，普通网络或 WAF 故障不会误删会话。登录页面只会由用户手动触发。

伴侣的独立说明见 [browser-companion/README.md](../browser-companion/README.md)。

## 安装与启动

### 发布版 EXE

普通用户应从 v2 GitHub Release 下载 `CodexCCSwitchUsage-Setup-<version>.exe` 并直接运行；macOS 用户下载与处理器匹配的 `CodexCCSwitchUsage-macos-arm64-<version>.tar.gz` 或 `CodexCCSwitchUsage-macos-x64-<version>.tar.gz`，解压后打开 `.app`。Windows 安装器会保留已有 `runtime` 缓存和偏好，在覆盖安装时只替换程序文件并重启插件宿主，不会关闭 Codex。需要浏览器登录态、Cookie 或 WAF 查询时，再下载同一 Release 中的浏览器伴侣 ZIP 或 CRX。

通过 EXE 安装的版本请从 Windows“已安装的应用”卸载，或运行安装目录中的 `unins000.exe`；不要对 EXE 安装使用源码目录的 `scripts\uninstall.ps1`。

### 源码开发/脚本安装

需要进行 v2 开发或从源码运行时，请先切换到 `v2` 分支，再从项目根目录运行。Codex 已在本机 `9334` 端口启用 CDP 时，下面的流程只重启插件宿主：

```powershell
$root = (Get-Location).Path
& .\scripts\stop-host.ps1 -InstallRoot $root -AllInstances
& .\scripts\launch.ps1 -InstallRoot $root
```

如果需要把源码复制到默认脚本安装目录，才运行 `scripts\install.ps1`。源码复制完成后，只有在用户明确允许重启 Codex 时，才给安装目录的 `launch.ps1` 传入 `-AllowCodexRestart`：

```powershell
& .\scripts\install.ps1
$installed = Join-Path $env:LOCALAPPDATA 'CodexCCSwitchUsage'
& "$installed\scripts\launch.ps1" -InstallRoot $installed -AllowCodexRestart
```

工作区或脚本安装目录的状态和停止插件宿主：

```powershell
& .\scripts\status.ps1 -InstallRoot $root
& .\scripts\stop-host.ps1 -InstallRoot $root -AllInstances
& "$installed\scripts\status.ps1" -InstallRoot $installed
& "$installed\scripts\stop-host.ps1" -InstallRoot $installed -AllInstances
```

脚本安装目录的卸载仍使用：

```powershell
& "$env:LOCALAPPDATA\CodexCCSwitchUsage\scripts\uninstall.ps1"
```

### macOS 源码模式

macOS 使用 Node.js 入口，不使用 Windows EXE 或 PowerShell。先让 Codex 以 `9334` 端口启用 CDP；应用名为 `Codex` 时可执行：

```bash
open -a "Codex" --args \
  --remote-debugging-port=9334 \
  --remote-allow-origins=http://127.0.0.1:9334 \
  --no-first-run
```

然后在项目根目录运行：

```bash
npm run stop-host:mac -- --install-root "$PWD" --all-instances
npm run launch:mac -- --install-root "$PWD"
```

`scripts/launch.mjs` 会等待 Codex 主页面出现在 CDP 目标列表中，再通过 `ps` 识别带该端口的 Codex 根进程并启动宿主；它不会关闭或重启 Codex。若应用进程名不同，使用 `--codex-pid <PID>` 显式指定根进程。macOS 默认读取 `~/.cc-switch/cc-switch.db` 和 `~/.codex`。这套入口已在 Windows 上用模拟平台测试，真实 macOS CDP、进程名和应用启动行为仍需在 Mac 实机确认。

源码开发、测试、热更新和 EXE 打包的完整约束见 [DEVELOPMENT.md](../DEVELOPMENT.md)。`npm run build:exe` 是维护者的显式打包步骤，不是普通运行所需的命令；每个发布包都必须与匹配的 Git tag、浏览器伴侣 ZIP 和签名 CRX 一起发布。

安装、覆盖安装或版本升级会创建或修复开始菜单中的“Codex + CCSwitch 用量”快捷方式。桌面快捷方式由安装选项控制。插件使用 Codex 默认 profile；从该快捷方式启动后，后续从系统通知、开始菜单或任务栏激活 Codex 都会复用同一个实例。
