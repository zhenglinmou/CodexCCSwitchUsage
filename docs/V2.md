# Codex CCSwitch Usage v2

[返回版本选择](../README.md) · [查看 v1 文档](./V1.md)

v2 在 Codex 输入栏余额条的基础上提供统一的 All API Hub / Balance Hub，用一套本机服务查询和管理 CCSwitch 中全部 Codex / GPT 供应商。

## v2.0.0 功能

- 自动读取 CCSwitch 中全部 `app_type=codex` 供应商，不维护第二份账号清单。
- 常规宽度下，余额与刷新按钮之间显示独立的 All API Hub 图标；只有点击该图标才打开 Hub，余额文字本身不跳转。
- 极限压缩时仍只显示刷新按钮；刷新按钮打开的余额弹层中保留“打开 All API Hub”入口。
- 原有响应式字段折叠顺序保持不变，整个余额根容器始终填满并居中于左右原生控件之间的动态空闲区。
- 并发查询全部供应商，统一展示已用、剩余、总额、来源和异常状态。
- 内置 OpenAI / CLIProxyAPI、DeepSeek、PackyCode、窗口额度站和 API 健康检查适配。
- API Key 与 Base URL 能直接查询的供应商优先请求第三方官网接口。
- API Key 无法查询余额或遇到 WAF 时，由安装在日常 Edge / Chrome profile 中的余额伴侣执行同源请求。
- Cookie 继续保存在原浏览器，不复制到 Node，也不需要维护第二个浏览器 profile。
- 不保持浏览器级或页面级 CDP WebSocket：每秒只读取一次短生命周期 `/json/list` 标题快照来接收刷新或 Hub 点击；只有启动、结果推送和五分钟安全审计才在唯一主页面上瞬时注入并立即断开。内置 Browse / WebView 存在时暂停全部注入。
- 每张供应商卡片的“查看”会列出实际请求地址、HTTP 方法、认证类型、执行位置、Cookie / WAF 依赖和当前结果来源，但不显示任何认证原文。
- 余额查询本身不会创建或激活网站标签页；只有用户点击“同步现有会话”或“去官网认证”后，才会复用现有标签页或显式打开官网登录页。
- AnyRouter、AgentRouter 等网页登录供应商始终显示独立的“官网登录/重新登录官网”入口；该入口不依赖 WAF 错误分类，也不会触发额度查询。
- 打开 Hub 只读取缓存状态，不自动刷新供应商。
- 只有 CCSwitch 当前选中的供应商固定每五分钟定时查询；Hub 中其他供应商仅在手动点击刷新时查询，浏览器伴侣重连不会触发余额请求。
- v2 监听 `127.0.0.1:17891`，完全替代旧 Python 余额桥接。

## 数据流

v2 的余额数据流只有一个中心：

```text
Codex 余额条 ─┐
All API Hub  ─┼→ v2 Balance Hub → 第三方官网 API / 现有浏览器回调
本机统一接口 ─┘
```

Hub 不执行、也不修改 CCSwitch 中已有的 `usage_script`。数据库原值保持不变；统一接口同时兼容已有的 `/usage/{alias}` 与 `/v1/balance/{alias}` 路径。

v1 的脚本执行方式和返回格式已单独保留在 [v1 文档](./V1.md) 与 [v1 `usage_script` 格式说明](../USAGE_SCRIPT_FORMAT.md) 中。

## 安全与运行边界

本项目仅支持 Windows。开发与运行需要 Node.js 22 或更高版本；使用项目启动脚本时，Codex 会通过本地 CDP 调试端口与插件宿主连接。

- 不修改 `app.asar`、MSIX 或 Codex 配置。
- CCSwitch 数据库只读。
- CDP 只连接已确认的 Codex 主文档；不会连接 Browse、MCP App、`about:blank`、外部网页或其他原生辅助 WebView。
- Hub 只监听 `127.0.0.1:17891`。管理页面和写操作使用首次启动生成并保存在 `runtime` 的随机路径令牌。
- API Key、Cookie 与 Token 只在本机宿主内存中用于请求，不发送到 Hub 页面，也不写日志。
- WAF 查询通过 `browser-companion` 使用现有 Edge / Chrome profile 的登录状态；Cookie 原文不会回传。
- 不运行额外的 Codex 实例守护进程。

## 本机只读余额接口

```text
GET /v1/health
GET /v1/providers
GET /v1/balance/{provider-id-or-alias}
GET /v1/balances
GET /usage/{provider-id-or-alias}
```

## 连接现有浏览器

AgentRouter、AnyRouter 等 WAF 站点需要一次性连接浏览器伴侣：

1. 在 `edge://extensions` 或 `chrome://extensions` 启用“开发人员模式”。
2. 选择“加载解压缩的扩展”，目录指向项目中的 `browser-companion`。
3. 打开 All API Hub，点击“连接现有浏览器”复制连接码。
4. 点击“CCSwitch 余额伴侣”图标，粘贴连接码并保存。

连接码只需保存一次。连接码、固定 `clientId` 和已成功验证站点的 origin 提示保存在当前浏览器 profile 的 `chrome.storage.local`；浏览器启动、MV3 后台唤醒或 Balance Hub 宿主重连时，伴侣会自动重新连接并恢复这些站点提示。

站点 Cookie 仍由 Edge / Chrome 自己持久化，伴侣不会把 Cookie 原文传给 Node。伴侣只保存允许列表中的 origin，以及 New API 余额接口所需的纯数字用户 ID；不会保存 localStorage 原文、Token 或其他认证数据。宿主重启后会恢复这些提示，再用真实同源响应验证登录状态；明确的认证失败会清除提示，普通网络或 WAF 故障不会误删会话。登录页面只会由用户手动触发。

伴侣的独立说明见 [browser-companion/README.md](../browser-companion/README.md)。

## 安装与启动

请先切换到 `v2` 分支，再从项目根目录运行：

```powershell
& .\scripts\install.ps1
& "$env:LOCALAPPDATA\CodexCCSwitchUsage\scripts\launch.ps1"
```

状态、停止和卸载：

```powershell
& "$env:LOCALAPPDATA\CodexCCSwitchUsage\scripts\status.ps1"
& "$env:LOCALAPPDATA\CodexCCSwitchUsage\scripts\stop.ps1"
& "$env:LOCALAPPDATA\CodexCCSwitchUsage\scripts\uninstall.ps1"
```

## 生成安装包

```powershell
winget install --id JRSoftware.InnoSetup --exact --scope user
npm run build:exe
```

安装包输出到 `dist\CodexCCSwitchUsage-Setup-<version>.exe`。覆盖安装只替换程序文件并重启插件宿主，不会关闭 Codex，也不会删除 `runtime` 中的缓存和状态。

通过 EXE 安装的版本请从 Windows“已安装的应用”中卸载；`scripts\uninstall.ps1` 只用于脚本安装方式。

安装、覆盖安装或版本升级会创建或修复开始菜单中的“Codex + CCSwitch 用量”快捷方式。桌面快捷方式由安装选项控制。插件使用 Codex 默认 profile；从该快捷方式启动后，后续从系统通知、开始菜单或任务栏激活 Codex 都会复用同一个实例。
